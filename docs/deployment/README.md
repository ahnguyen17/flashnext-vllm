## q4exp Quirks (cost hours to learn)

- `-fa on` — lowercase with value; `-Fa` is invalid in this fork
- `-ctk q8_0`/`-ctv q8_0` KV quant → GGML_ASSERT at qwen4exp.cpp:544 — DO NOT USE (main model; draft KV q8 via `-ctkd/-ctvd` is fine)
- Default `n_slots=4` splits context 4 ways — `--parallel 1` for max single-request context
- **`per_layer_token_embd.weight` is the 24.8 GiB n-gram/PLE lookup table** (dims 160×320,001,536) — NOT a normal embedding. The CPU override is MANDATORY (cannot fit the 40G card; loader fit-abort degrades layout) and IS the r/LocalLLM "ngram offload" technique — free on CUDA via override, no GGUF repack. VRAM math: 104G − 24.8G table + 9.7G KV@256K = 88.9G observed. Per-layer `blk.N.ple_*` tensors are tiny (~0.04G) and stay on GPU.
- Benchmark gotcha: temp-1.0 default sampling on /completion can stop instantly (EOS) → looks like "0.0 tok/s / empty output"; always `"temperature": 0`
- **Prefix-cache gotcha: llama.cpp slot prefix reuse silently skips shared prompt prefixes across requests** — benchmark prompts MUST be prefixed with a per-case unique nonce or short-prefill numbers are fake-good
- Two operating modes (launch script arg 2 = n_max): deep = `262144` no draft (**the frozen floor, 36.0 tok/s — run this by default**); fast = `131072 <n>` with 9B draft (`--spec-type draft-simple -md <draft> -ngld 99 -ctkd q8_0 -ctvd q8_0 --spec-draft-n-max N`) — draft KV at 256K does NOT fit VRAM, hence the 128K cap. **Fast mode benched and REJECTED 8/28 (see speculative verdicts below) — do not serve it without a new draft model.**
- **Vision LIVE (enabled + verified 8/28 PM):** the vision encoder ships as a separate `mmproj-F16.gguf` (904M, at repo ROOT — per-quant shard downloads never include it). Serve with `--mmproj ~/models/Flash-Next-NVMe/UD-Q4_K_XL/mmproj-F16.gguf`; `/v1/models` capabilities must read `['completion','multimodal']` (alias `flash-next`). Verified end-to-end through the tailnet URL with a rendered-text test card — model read name/MRN/room back exactly. Test gotchas: thinking models burn a small `max_tokens` entirely on `reasoning_content` → empty `content` ≠ broken vision — and ≠ broken LANE on plain-text health gens either (a `max_tokens:10` post-restore check returned empty content 8/29 and looked dead; give ≥300 or read `reasoning_content`); verify with a text card, not an arbitrary image (a model accurately describing a boring image looks like a failure)
- **Speculative decoding verdicts (all benched 8/28, nonce'd yardstick):** ngram-cache = zero gain on chat. **9B-distill draft = REJECTED — 8.6 tok/s (5× SLOWER than floor), acceptance collapsed 0.64 warmup → 0.11–0.14 real text.** Tokenizer alignment RULED OUT (0.64 warmup acceptance proves token IDs align; misalignment rejects everything) — it's a capability gap: a 9B distill cannot track the 176B MoE's greedy tokens on technical content. Every rejected draft round pays full verify cost. DO NOT RETRY this draft. The viable path is a real Flash-Next draft: MTP-head GGUF when upstream ships one (`--spec-type draft-mtp`), same family/shared embedding, like prod's MTP k=3 (acceptance 3.1). Same lesson as the k-sweep: acceptance quality beats everything. The serve script's fast mode (128K + draft) is kept only as a template for that future draft; full data in repo `EXPERIMENTS.md` experiment 8.
- HF download throttles ~10 MB/s PER-IP (parallel streams split it); hf_transfer deprecated in hub 1.27; Xet HANGS on this rig (HF_HUB_DISABLE_XET=1 always)
- Restarting the lane: a background-terminal pid is often a WRAPPER (`chmod … && script` chain spawns a child that `exec`s) — get the real listener pid from `ss -tlnp` or the port stays held after killing the wrong one
- `bench/bench.py` now carries the lane auth (`FN_KEY` env, default `change-me`) — required since `--api-key` went on; `/props` and `/completion` both need the header. Next queued lever: KV q8_0 (fork assert qwen4exp.cpp:544; third-party benches prove the MODEL supports `-ctk q8_0`, so it's a fork fix away from ~4-5GB freed @256K)
